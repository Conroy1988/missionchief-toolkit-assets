Alliance Member Manager

Enable Alliance Member Manager from Map → Alliance Operations. On an alliance member-list page it adds English role, activity, sorting and direction controls without replacing MissionChief profile or administration actions.

  • Filter by alliance role or current online/offline state.
  • Sort by original order, member name, alliance role or current activity.

Alliance Admin and Alliance Courses

Changed or ambiguous forms are skipped; a failed or unverified result is never retried automatically.

Dispatch Recruitment

Open Toolkit → Dispatch, load the current native options, choose one centre or ALL DISPATCH CENTRES, then choose ALL BUILDING TYPES or one exact type such as Fire Station, Police Station or Ambulance Station before scanning. The selector is populated from MissionChief rather than a hard-coded regional list. A single-centre scan loads that centre's exact Buildings matrix. The all-centres scan loads every centre-specific matrix sequentially, displays progress such as Scanning 12 of 38 · Centre name, merges exact assignment evidence and deduplicates station IDs globally before admitting only the chosen type. Changing either scope discards the old queue and keeps Apply disabled until the replacement scan succeeds.

If one matrix fails, times out, redirects unexpectedly, is malformed or contradicts another matrix, the complete result is discarded and Apply to Selected remains disabled. Native No control center rows never enter the queue. Post-scan type filters and exact station checkboxes can refine the plan further. Apply confirms the centre scope, exact stations, types, Hiring Phase and Personnel (Desired). The Toolkit never calls MissionChief's assignment endpoint or sends an assignment field. It verifies the exact Dispatch Centre and building type after every mutation, reports safe one-field success as Partial, and stops the complete bulk run if assignment state changes or a submitted action cannot be verified.

Station Icon Copier

Open Toolkit → Dispatch, load owned stations, choose one Dispatch Centre or ALL DISPATCH CENTRES, then choose a source station whose existing custom icon is already correct. The source defines the exact native building type and small/full classification automatically. Scan shows the source thumbnail, exclusions and every eligible target. The source itself, unassigned stations, other types and the full/small counterpart are excluded. Existing custom icons are protected by default; explicit replacement mode admits them to the individually selectable preview.

Apply validates the source PNG or JPEG against MissionChief's 200×200 limit, downloads it once into memory and confirms the exact target count. Each target is freshly rechecked, its current same-origin native building-edit form is preserved, and only Building Image is replaced. After submission, identity, Dispatch Centre, type, size, name and coordinates must remain unchanged, and the saved rendered pixels must match the source before the next target begins. A submitted but unverified upload stops the complete run and is never retried automatically.

Patient Transport Sweep — background first, native fail-safe

Background first is enabled by default. For each verified alliance-owned FMS 5 patient vehicle, the Toolkit fetches that exact vehicle page and accepts only one same-origin native Cancel Transport link whose path names the same vehicle and a numeric patient. A fresh MissionChief confirmation is required before the release is counted. This avoids opening mission and vehicle lightboxes on the supported path.

If no authoritative background link exists before the request, the sweep opens the mission and vehicle and uses the proven visible Cancel Transport or Discharge patient workflow, including MissionChief's Patient isn’t transported completion state. If a background request was sent but its result cannot be verified, that patient is marked as an error and is never retried through either path. The visible-only mode remains selectable. Personal vehicles, malformed or external URLs, conflicting actions and prisoner transports remain excluded.

When the sweep finishes, its aggregate report remains visible until dismissed or replaced and survives a page reload. It records missions checked, eligible and completed missions, patients cleared, skipped actions, errors, processed patients, success rate, duration, completion time and final status. If a valid Discord webhook is already saved in Finance, the same snapshot posts automatically once. No mission name, mission ID, player identity or alliance identity is included. A failed webhook never changes the sweep result and exposes a deliberate retry.

See the complete background-action and fallback safety contract.

Incident Command Wire — unattended missions

The wire excludes a qualifying mission only after one of your own vehicles reaches MissionChief’s FMS 4 on-scene state. Selection and FMS 3 responding do not remove it, alliance-only attendance is ignored, and the mission can re-enter when your final on-scene unit leaves. The continuous reel, counter and expanded queue remain synchronized without routine layout reconciliation seeking the reel backwards.

Operational Pressure Board and SITREP

The board always includes personal missions. A persistent Alliance Missions switch adds joined Alliance missions only when deliberately enabled and is off by default. Available personal vehicles are allocated once across the selected demand picture, so a single specialist unit cannot cover several missions on paper. Focus, Open and Pin are navigation only. The SITREP uses the same snapshot and the saved Finance webhook only after the manual Generate & Post action.

Procurement Brain and Operational Timeline

Open the board with B, use the Missions panel or search the Command Palette. Procurement ranks current confirmed shortages, fleet conflicts, reserve depth and recent repeated vehicle or personnel demand across 24-hour, 7-day or 30-day windows. Every recommendation includes priority, confidence and evidence, with UK Intel available for vehicle context. It is advisory and cannot purchase, move, select or dispatch a unit.

Timeline Logging is persistent and off by default. While disabled, the Toolkit skips mission-history processing. After it is enabled, Timeline establishes a quiet first-scan baseline, then records newly observed missions, response commitment and arrival, requirement and casualty changes, stalls, recoveries and confirmed disappearance. Turning logging off stops new events without deleting retained history. Identical events are deduplicated and a transient missing marker does not become an immediate completion. Filter, search, focus live missions or export JSON. Records stay local, expire after 30 days, are capped at 1,500 and can be cleared only after confirmation; clearing also removes Procurement Brain's historical learning evidence. The feature reuses existing mission snapshots and adds no poller or observer.

See the complete evidence, retention and safety contract.

MissionChief UK Knowledge Link

Every known Pressure Board requirement exposes a read-only dossier containing qualifying units, numeric type IDs, capability alternatives, crew ranges, training courses, academies, durations and associated personnel. Opening the dossier uses a fresh cached copy where possible; Refresh Guide data explicitly requests the three schema-validated public Guide collections. A bounded stale copy and the embedded catalogue preserve useful evidence when the Guide is unavailable. Unknown live labels remain visible as Catalogue Drift and the report link opens a review-before-submit GitHub form without player identifiers.

Same-value UI write suppression

Toolkit v10.6.4 retains the v8.3.2 guarantee: it locates the current live command bar and settings panel on every update, but writes a class, attribute, style, text value or form value only when it differs. This avoids repeated DOM mutation traffic without caching stale MissionChief elements.

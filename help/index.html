One command interface, organised around the job

Fast Map replacement renderer

Select Fast Map beside Economy Mode. Toolkit stops native Leaflet animation, disables its handlers, parks the exact map element outside the rendered document and blocks detached marker DOM writes. The replacement loads OpenFreeMap Bright, validates its vector source, mounts the live building, mission, vehicle and route layers, and waits for an idle WebGL render before activation. There are zero connected Leaflet panes underneath the MapLibre canvas.

Fast Map reads the current MissionChief Leaflet icon for every building, mission and vehicle, deduplicates shared pictures into the WebGL sprite, and follows each travelling vehicle’s native red destination polyline. PNG/APNG, JPEG, GIF and WebP candidates pass a signature and size boundary. Once a picture is ready, Fast Map retains it while the next candidate decodes, retries transient failures with capped backoff and prunes superseded descriptors after atomic promotion.

The Fast Map health, metrics, zoom and Native controls sit at the top centre of the map, with OpenStreetMap and OpenFreeMap attribution directly beneath them. Select Native, press Fast Map again, open Drawing or Coverage, or encounter a style or renderer failure to restore the exact Leaflet element, view and enabled handlers.

Heavier Toolkit overlays still belong to the native Leaflet workspace; switching back restores them without changing their saved settings.

Dispatch Recruitment restoration

Open Administration → Dispatch Recruitment, work through Scope and Configure, choose the exact centre and building-type scope, set Hiring Phase and Personnel (Desired), then scan and review. Matching stations remain visible but unchecked; any station differing on either value is selected. Manual Select all, Clear, type filters and per-station selection remain available. Apply still rechecks every station's Dispatch Centre and type, accepts only one exact same-origin Personnel (Desired) form, appends only the required personnel-only flag when MissionChief omits it, uses the current protected Rails CSRF token, submits sequentially and verifies the result before moving on.

Complete UK Building quick filters

Press 4, tap Buildings, use the Quick Wheel or choose Open Building Filters in the command palette. Ambulance Stations, Police Stations and Fire Stations remain the featured first three; Hospitals, small stations, air, academy, rescue, support and specialist buildings follow in a fixed UK gameplay popularity order.

All 31 active UK building type IDs are covered by 30 rows because MissionChief combines Large and Small Building Complexes in one native control. Each available row reads and activates MissionChief’s matching checkbox, and the popup stays open for multi-selection. A row is marked Unavailable only when the current map does not expose that native filter. Shift+4 and right-clicking the dock control open the same popup.

The Toolkit scans native controls once per render and supports exact main/small labels, current filter identifiers, live translations and UK/US spelling variants. It creates no replacement building layer; legacy selector data remains import-compatible but inert, and Economy Mode leaves building visibility under MissionChief’s filter service.

Privacy-safe first-party analytics

The Toolkit reports only aggregate version adoption, coarse device and route classes, bounded feature demand, startup performance bands and bounded error categories. It sends no visitor identifier, player name, alliance or gameplay data, IP-derived identity, free text, full user agent, referrer or analytics cookie. Global Privacy Control and Do Not Track stop local analytics state and transmission.

Dispatch Recruitment

Open Toolkit → Administration → Dispatch Recruitment, load the current native options, choose one centre or ALL DISPATCH CENTRES, then choose ALL BUILDING TYPES or one exact type such as Fire Station, Police Station or Ambulance Station before scanning. The selector is populated from MissionChief rather than a hard-coded regional list. A single-centre scan loads that centre's exact Buildings matrix. The all-centres scan loads every centre-specific matrix sequentially, displays progress such as Scanning 12 of 38 · Centre name, merges exact assignment evidence and deduplicates station IDs globally before admitting only the chosen type. Changing either scope discards the old queue and keeps Apply disabled until the replacement scan succeeds.

If one matrix fails, times out, redirects unexpectedly, is malformed or contradicts another matrix, the complete result is discarded and Apply to Selected remains disabled. Native No control center rows never enter the queue. Post-scan type filters and exact station checkboxes can refine the plan further. Apply confirms the centre scope, exact stations, types, Hiring Phase and Personnel (Desired). The Toolkit never calls MissionChief's assignment endpoint or sends an assignment field. It verifies the exact Dispatch Centre and building type after every mutation, reports safe one-field success as Partial, and stops the complete bulk run if assignment state changes or a submitted action cannot be verified.

Station Icon Copier

Open Toolkit → Administration → Station Icon Copier, load owned stations, choose one Dispatch Centre or ALL DISPATCH CENTRES, then choose a source station whose existing custom icon is already correct. The source defines the exact native building type and small/full classification automatically. Scan shows the source thumbnail, exclusions and every eligible target. The source itself, unassigned stations, other types and the full/small counterpart are excluded. Existing custom icons are protected by default; explicit replacement mode admits them to the individually selectable preview.

Apply validates the source PNG or JPEG against MissionChief's 200×200 limit, downloads it once into memory and confirms the exact target count. Each target is freshly rechecked, its current same-origin native building-edit form is preserved, and only Building Image is replaced. After submission, identity, Dispatch Centre, type, size, name and coordinates must remain unchanged, and the saved rendered pixels must match the source before the next target begins. A submitted but unverified upload stops the complete run and is never retried automatically.

Expansion & Upgrade Planner

Open Toolkit → Administration → Expansion & Upgrade Planner, load owned stations, choose one Dispatch Centre or ALL DISPATCH CENTRES, choose an exact building type or ALL BUILDING TYPES, then scan the required station limit. The planner spans the responsive Administration workspace: wide workspaces show four primary actions, three columns of planning fields and two columns of live station results; medium and narrow workspaces reflow those groups automatically. Selection controls, the Credit briefing, reports and purchase safeguards retain the complete width below them.

For levels and vehicle bays, the planner follows only the exact native /buildings/<id>/expand link exposed by that station and reads MissionChief's direct expand_do/credits?level=<target-index> GET control there. The target is zero-indexed: the immediate next displayed level uses the current authoritative API level as the query value. Extensions remain native POST actions. Static costs, Coin or gold routes, later cumulative targets, extra query fields, pending construction, external or redirected pages and ambiguous duplicate actions are excluded.

A scan approves nothing by default and reports native expansion pages opened, Credit-labelled controls inspected, and price, route or method rejections. Select at most one level, bay or extension operation per station and enter a hard Credit budget. Purchase performs a fresh exact-scope, discovery-page and action revalidation before showing the final operation list, total, budget and unspent amount. Each selected station and its bound native discovery page are fetched again immediately before sequential submission, then the authoritative building record and page must prove an exact one-level increase before the next purchase starts. A changed price or state fails before submission; an ambiguous submitted response stops the complete run and is never retried automatically. The retained result report remains until dismissed.

Patient Transport Sweep — background first, native fail-safe

Background first is enabled by default. For each verified alliance-owned FMS 5 patient vehicle, the Toolkit fetches that exact vehicle page and accepts only one same-origin native Cancel Transport link whose path names the same vehicle and a numeric patient. A fresh MissionChief confirmation is required before the release is counted. This avoids opening mission and vehicle lightboxes on the supported path.

If no authoritative background link exists before the request, the sweep opens the mission and vehicle and uses the proven visible Cancel Transport or Discharge patient workflow, including MissionChief's Patient isn’t transported completion state. If a background request was sent but its result cannot be verified, that patient is marked as an error and is never retried through either path. The visible-only mode remains selectable. Personal vehicles, malformed or external URLs, conflicting actions and prisoner transports remain excluded.

When the sweep finishes, its aggregate report remains visible until dismissed or replaced and survives a page reload. It records missions checked, eligible and completed missions, patients cleared, skipped actions, errors, processed patients, success rate, duration, completion time and final status. If a valid Discord webhook is already saved in Finance, the same snapshot posts automatically once. No mission name, mission ID, player identity or alliance identity is included. A failed webhook never changes the sweep result and exposes a deliberate retry.

See the complete background-action and fallback safety contract.

Incident Command Wire — unattended missions

The wire excludes a qualifying mission only after one of your own vehicles reaches MissionChief’s FMS 4 on-scene state. Selection and FMS 3 responding do not remove it, alliance-only attendance is ignored, and the mission can re-enter when your final on-scene unit leaves. The continuous reel, counter and expanded queue remain synchronized without routine layout reconciliation seeking the reel backwards.

Operational Pressure Board and SITREP

The board always includes personal missions. A persistent Alliance Missions switch adds joined Alliance missions only when deliberately enabled and is off by default. Available personal vehicles are allocated once across the selected demand picture, so a single specialist unit cannot cover several missions on paper. Focus, Open and Pin are navigation only. The SITREP uses the same snapshot and the saved Finance webhook only after the manual Generate & Post action.

Procurement Brain and Operational Timeline

Open the board with B, use the Missions panel or search the Command Palette. Procurement ranks current confirmed shortages, fleet conflicts, reserve depth and recent repeated vehicle or personnel demand across 24-hour, 7-day or 30-day windows. Every recommendation includes priority, confidence and evidence, with UK Intel available for vehicle context. It is advisory and cannot purchase, move, select or dispatch a unit.

Timeline Logging is persistent and off by default. While disabled, the Toolkit skips mission-history processing. After it is enabled, Timeline establishes a quiet first-scan baseline, then records newly observed missions, response commitment and arrival, requirement and casualty changes, stalls, recoveries and confirmed disappearance. Turning logging off stops new events without deleting retained history. Identical events are deduplicated and a transient missing marker does not become an immediate completion. Filter, search, focus live missions or export JSON. Records stay local, expire after 30 days, are capped at 1,500 and can be cleared only after confirmation; clearing also removes Procurement Brain's historical learning evidence. The feature reuses existing mission snapshots and adds no poller or observer.

Same-value UI write suppression
